# Extension and backend architecture

The VS Code frontend is bundled from `src/extension.ts` into the root extension package. It provides setup and commit analysis commands, stores API keys and the optional GitHub token in VS Code SecretStorage, and starts the Python ARGUS pipeline as short lived processes. Configuration keeps execution mode (API or local CLI) separate from the provider selected within that mode. Its model picker refreshes from provider API model catalogs or the local Codex catalog, with CLI catalog entries, Claude model IDs and aliases, and custom model IDs available as fallbacks.

The backend is the bundled Python pipeline under `python/scripts/ARGUS`. On first extension activation, the frontend creates a private environment in VS Code global storage and installs `python/requirements.txt`; later activations reuse it unless the requirements change. The frontend then runs artifact retrieval, rationale sentence identification, and rationale generation in order, passing the commit URL, provider, mode, model, run count, and selected credentials in the child process environment. The shared `llm_provider.py` adapter routes prompts to OpenAI, Anthropic, Codex CLI, or Claude Code CLI. No HTTP server, port, or separate backend repository is required.

The generated artifacts and summary are stored under `globalStorage/runtime/results/<owner>__<repo>__<sha-prefix>/`. Setup and task output is written to the Rationale output channel and failures are shown in VS Code error notifications. A one-time first-use message offers credential setup or commit analysis.
